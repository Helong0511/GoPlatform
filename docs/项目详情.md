# GoPlatform 项目详情

## 1. 项目定位

GoPlatform 是一个广告投放与任务调度后端服务，面向以下业务角色：

- 上游：广告主
- 下游：客户 / 渠道 / 商户

系统核心能力是为终端分发广告任务、回收执行上报、提供后台管理能力（用户、角色、部门、客户等）以及运行监控能力。

## 2. 技术栈与运行环境

- 后端语言：Go（`go 1.25.0`）
- Web 框架：Gin
- 数据访问：GORM
- 数据库：PostgreSQL / MySQL8.0（由 `database.driver` 或 `DB_DRIVER` 识别）
- 缓存：Redis
- 消息队列：Apache Pulsar（当前 `main` 中固定跳过初始化，保留接口）
- 认证：JWT
- 安全能力：AES + Rust 动态库（`rust-security`）
- 可观测性：Prometheus 指标接口 + 告警规则（默认 `9090/metrics`）
- 日志：结构化日志（`slog`，支持 `json/text`）+ 请求级访问日志 + panic 恢复日志

## 3. 代码结构说明

主要目录说明如下：

- `cmd`：程序入口（当前为 `cmd/main.go`）
- `api`：HTTP 路由与控制器层
- `internal`：核心业务实现（广告、后台管理、报表、安全）
- `pkg`：通用基础能力（数据库、Redis、Pulsar、中间件、工具函数、指标）
- `config`：配置文件（`config/config.yaml`）
- `admin`：前端管理端代码
- `sql`：数据库脚本与结构（项目约定数据库内容放此目录）
- `tests`：测试程序（项目约定测试内容放此目录）
- `scripts`：部署/运维辅助脚本
- `monitoring`：Prometheus 告警规则
- `ubuntu`：部署与接口对接说明

## 4. 服务启动流程（后端）

`cmd/main.go` 的主流程：

1. 解析配置路径（`CONFIG_PATH` > `config/config.yaml` > `config.yaml`）
2. 加载配置并应用环境变量覆盖（如 `DB_*`、`JWT_SECRET`、`AES_SECRET_KEY`、`AUTH_ALLOW_PUBLIC_REGISTER`、`EMAIL_*`）
3. 设置默认值并执行配置校验（端口、驱动、连接池、限流、邮件等）
4. 启动 Prometheus 指标服务
5. 初始化数据库（当前入口使用 `db.NewPostgresDB`）
6. 初始化 Redis（失败时降级为 `mock redis`）
7. 初始化安全管理器（Rust 动态库失败时降级）
8. 初始化业务服务（用户、角色、部门、广告、报表）
9. 初始化限流器与密钥解析（JWT/AES，优先环境变量）
10. 初始化 Gin 引擎并挂载中间件：
   - 请求 ID 中间件（`X-Request-ID` 透传/生成）
   - 访问日志中间件（慢请求阈值可配置，自动记录错误上下文）
   - panic 恢复中间件（输出堆栈）
   - CORS 中间件
   - IP 级限流中间件
   - 多语言中间件（默认简体中文）
11. 注册路由并启动 HTTP 服务（默认 `0.0.0.0:8960`）
12. 监听 `SIGINT/SIGTERM`，执行优雅停机（关闭报表服务、Redis、数据库、安全管理器）

## 5. 接口与模块能力

根据 `api/routes.go`，接口分层如下：

- 系统模块：系统基础能力与健康相关接口
- 鉴权模块：登录/注册及管理员认证路由
- 管理模块：用户、角色、部门、客户管理接口

- 广告模块：任务获取、任务处理相关接口
- 报表模块：任务上报、统计处理相关接口
- 中间件能力：
  - JWT 用户上下文中间件（`UserContextMiddleware`）
  - RBAC 权限中间件（`RBACMiddleware`）
  - 部门隔离中间件（`DepartmentMiddleware`）
  - API Key 下游身份中间件（`APIKeyMiddleware`，支持 scope 校验与来源 IP）

根据 `ubuntu/api-spec.txt`，对接侧重点包括：

- 获取任务：`/getWebTask`
- 上报任务：`/upWebTask`
- 请求和响应主体使用加密数据字段（`data`），涉及 AES 解密/加密处理

## 6. 关键配置项（config/config.yaml）

- 服务配置：`server.host`、`server.port`、`server.timeout`
- 认证配置：`auth.allow_public_register`
- 邮件配置：`email.enabled`、`email.host`、`email.port`、`email.username`、`email.from`
- 数据库配置：`database.driver`、`database.*`（连接池、集群节点）
- Redis 配置：`redis.*`（连接池、超时、重试）
- Pulsar 配置：`pulsar.*`
- JWT 配置：`jwt.secret`、`jwt.expires_in`
- 安全配置：`security.rust_lib_path`、`security.aes_secret`
- 监控配置：`metrics.port`、`metrics.path`
- 日志配置：`logging.level`、`logging.format`、`logging.slow_request_ms`
- 限流配置：`rate_limit.requests_per_second`、`rate_limit.burst`
- 跨域配置：`cors.allow_origins`

## 7. 部署与运维概览

结合 `docs/Ubuntu22.04.5超级详细部署指南.md`、`scripts/prometheus.yml`、`monitoring/alerts/prometheus-rules.yml`：

- 使用 `systemd` 管理主服务（`ad-platform-main.service`）
- 常规流程：构建二进制 -> 重启服务 -> `journalctl` 排障
- 涉及 Nginx、PostgreSQL、Redis、Pulsar 等依赖
- Prometheus 采集建议：
  - 主服务指标：`127.0.0.1:9090/metrics`
  - 规则文件：`monitoring/alerts/prometheus-rules.yml`
- 当前内置告警覆盖认证失败、API Key 权限拒绝、限流触发、5xx 错误率异常

## 8. 日志与错误可观测性

- 访问日志会记录：
  - 请求 ID、路由、状态码、耗时、客户端 IP、请求/响应体大小
  - 业务响应码、错误分类（category）、错误原因（reason）
- 敏感信息处理：
  - `Authorization`、`X-API-Key` 做脱敏
  - query 中包含 token/secret/password/api_key 的参数做掩码
- 指标联动：
  - 当 HTTP 状态码 `>= 400` 时，上报 `http_errors_total`
  - 标签维度：`error_code`、`error_category`、`error_reason`
- panic 恢复：
  - 统一捕获 panic 并输出堆栈，返回 `500 internal server error`

## 9. 当前状态与建议

1. **数据库驱动与脚本要一致**  
   当 `database.driver=postgres` 时使用 `sql/init_db_PostgreSQL.sql`；当 `database.driver=mysql` 时使用 `sql/init_db_mysql.sql`，避免驱动与库结构不匹配。

2. **敏感信息治理**  
   建议数据库密码、JWT/AES、SMTP 密钥全部走环境变量或密钥服务，避免配置文件明文。

3. **Pulsar 启用策略**  
   当前主程序明确跳过 Pulsar 初始化；若生产依赖消息链路，建议增加开关并补充连通性自检与失败降级策略。

4. **测试覆盖现状与补全方向**  
   已有 `tests/logging_middleware_test.go`、`tests/response_context_test.go` 覆盖请求 ID 与响应上下文。建议继续补充 API 集成测试、加解密兼容性测试、任务分发与回传链路测试。
