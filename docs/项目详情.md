# GoPlatform 项目详情

## 1. 项目定位

GoPlatform 是一个广告投放与任务调度后端服务，面向以下业务角色：

- 上游：广告主
- 下游：客户 / 渠道 / 商户

系统核心能力是为终端分发广告任务、回收执行上报、提供后台管理能力（用户、角色、部门、客户等）以及运行监控能力。

## 2. 技术栈与运行环境

- 后端语言：Go（`go 1.25.0`）
- Web 框架：Gin
- 数据访问：GORM
- 数据库：PostgreSQL（代码默认）  
  - 注：`ubuntu/info.txt` 中存在 MySQL 信息，属于部署侧信息，建议统一数据库方案
- 缓存：Redis
- 消息队列：Apache Pulsar（当前 `main` 中开发模式默认跳过初始化）
- 认证：JWT
- 安全能力：AES + Rust 动态库（`rust-security`）
- 可观测性：Prometheus 指标接口（默认 `9090/metrics`）

## 3. 代码结构说明

主要目录说明如下：

- `cmd`：程序入口（当前为 `cmd/main.go`）
- `api`：HTTP 路由与控制器层
- `internal`：核心业务实现（广告、后台管理、报表、安全）
- `pkg`：通用基础能力（数据库、Redis、Pulsar、中间件、工具函数、指标）
- `config`：配置文件（`config/config.yaml`）
- `admin`：前端管理端代码
- `sql`：数据库脚本与结构（项目约定数据库内容放此目录）
- `tests`：测试程序（项目约定测试内容放此目录）
- `scripts`：部署/运维辅助脚本
- `ubuntu`：部署与接口对接说明

## 4. 服务启动流程（后端）

`cmd/main.go` 的主流程：

1. 加载并校验 `config/config.yaml`
2. 启动 Prometheus 指标服务
3. 初始化 PostgreSQL、Redis（失败可降级为 mock）
4. 初始化安全管理器（Rust 动态库失败时降级）
5. 初始化业务服务（用户、角色、部门、广告、报表）
6. 创建 Router 并注入 JWT/AES 能力
7. 挂载 CORS、限流中间件
8. 启动 HTTP 服务（默认 `0.0.0.0:8960`）
9. 监听信号并优雅停机

## 5. 接口与模块能力

根据 `api/routes.go`，接口分层如下：

- 系统模块：系统基础能力与健康相关接口
- 鉴权模块：登录/注册及管理员认证路由
- 管理模块：用户、角色、部门、客户管理接口

- 广告模块：任务获取、任务处理相关接口
- 报表模块：任务上报、统计处理相关接口

根据 `ubuntu/api-spec.txt`，对接侧重点包括：

- 获取任务：`/getWebTask`
- 上报任务：`/upWebTask`
- 请求和响应主体使用加密数据字段（`data`），涉及 AES 解密/加密处理

## 6. 关键配置项（config/config.yaml）

- 服务配置：`server.host`、`server.port`、`server.timeout`
- 认证配置：`auth.allow_public_register`
- 数据库配置：`database.*`（连接池、集群节点）
- Redis 配置：`redis.*`（连接池、超时、重试）
- Pulsar 配置：`pulsar.*`
- JWT 配置：`jwt.secret`、`jwt.expires_in`
- 安全配置：`security.rust_lib_path`、`security.aes_secret`
- 监控配置：`metrics.port`、`metrics.path`
- 限流配置：`rate_limit.requests_per_second`、`rate_limit.burst`
- 跨域配置：`cors.allow_origins`

## 7. 部署与运维概览

结合 `ubuntu/deployment-notes.txt`：

- 使用 `systemd` 管理主服务（`ad-platform-main.service`）
- 常规流程：构建二进制 -> 重启服务 -> `journalctl` 排障
- 涉及 Nginx、PostgreSQL、Redis、Pulsar 等依赖
- 常用运维命令集中在 `ubuntu/deployment-notes.txt`

## 8. 当前状态与建议

1. **数据库信息需统一**  
   代码默认 PostgreSQL，部署信息中出现 MySQL，建议尽快统一并在文档明确唯一权威版本。

2. **敏感信息治理**  
   `ubuntu/info.txt` 中存在明文数据库账号密码，建议改为环境变量或密钥服务管理，避免仓库保存明文凭据。

3. **Pulsar 启用策略**  
   当前主程序明确跳过 Pulsar 初始化，若生产依赖消息链路，建议增加可配置开关并补充连通性自检。

4. **测试覆盖补全**  
   建议在 `tests` 目录补充 API 集成测试、加解密兼容性测试、任务分发与回传链路测试。
